# 찍고 (zzikko)

우리 동네 휴대폰 성지 시세와 이웃의 경험을 나누는 **네이버 카페형 커뮤니티**.

| 폴더 | 스택 | 상태 |
| --- | --- | --- |
| `frontend` | Next.js 16 (App Router) · React 19 · Tailwind 4 · TypeScript | 화면 구성 완료 (더미 데이터) |
| `backend` | Fastify 5 · TypeScript | 예정 |
| `app` | Flutter | 예정 |

웹과 앱이 같은 `/api/v1` REST API 를 쓰는 구조로 간다. 화면은 `frontend/src/lib/data.ts` 한 곳에서만
데이터를 읽으므로, 백엔드가 붙으면 그 파일만 fetch 로 바꾸면 된다.

## 실행

```sh
cd frontend
npm install
npm run dev     # http://localhost:4050
```

`npm run typecheck`, `npm run build` 로 검증한다.

> 포트: 프론트 **4050**, 백엔드 **4080** 예정. (다른 프로젝트가 3000·4000·4100 을 쓰고 있어 겹치지 않게 잡았다.)

## 화면

| 주소 | 내용 |
| --- | --- |
| `/` | 홈 — 배너, 공지, 방금 올라온 시세, 인기글, 게시판별 최신글, 중고장터 |
| `/board/[slug]` | 게시판. 소분류의 `type` 에 따라 목록/시세표/갤러리로 다르게 그린다 |
| `/board/[slug]/[id]` | 글 상세. 시세 글이면 가입 조건 표가 함께 나온다 |
| `/write` | 글쓰기 — 게시판 설정에 따라 에디터 / 사진 업로더 (저장은 백엔드 연결 후) |
| `/search`, `/mypage`, `/guide` | 검색, 마이페이지, 이용 안내 |
| `/admin` | 어드민 대시보드 (**인증 없음** — 배포 전 권한 검사 필요) |
| `/admin/boards` | 게시판 이름·형식·말머리 관리 |
| `/admin/news`, `/admin/specs` | IT 소식 기사 / 기종 사양 등록·수정·삭제 |

## 게시판 구성 (대분류 → 소분류)

| 대분류 | 소분류 | 말머리 |
| --- | --- | --- |
| 📢 공지 & 안내 | 공지사항, 가입인사 | — |
| 📱 휴대폰 | **성지 시세표**(판매자 전용), **IT 소식**(매거진), **스펙 비교**(기종 DB) | 시세표 말머리는 지역(서울·경기·인천·부산…) |
| 💬 커뮤니티 | 질문·답변, 이용 후기, 자유게시판 | 가입조건·요금제·기기선택 / 좋았어요·아쉬웠어요·주의 |
| 🛒 장터 & 생활 | 중고장터(갤러리), 인터넷·결합 | 공기계·액세서리·나눔 / 신규·재약정·결합 |

소분류마다 목록을 그리는 방식(`Board.type`)을 고를 수 있다.

- `list` — 일반 게시판 (기본값)
- `deal` — 시세표. 기종·통신사·할부원금을 목록에서 바로 비교한다
- `gallery` — 썸네일 격자
- `news` — 매거진. 대표 기사 + 카드 격자. **글이 아니라 어드민에서 관리하는 기사**를 보여준다
- `spec` — 기종 사양. 카드 목록에서 최대 3대를 골라 나란히 비교한다. **어드민에서 관리**

예를 들어 성지 시세표를 시세표 형태로 바꾸려면 `frontend/src/data/mock.ts` 에서
해당 게시판의 `type: 'list'` 를 `'deal'` 로만 바꾸면 된다.

새 게시판도 `boardGroups` 에 추가하면 사이드바·모바일 메뉴·자주 쓰는 메뉴가 모두 따라간다.

## 에디터 · 사진 업로더

abyssblue 에서 가져온 두 모듈이다. 각각 폴더 하나로 독립돼 있고, 프로젝트에 묶이는 건
`uploadImage` prop 하나뿐이다.

- `src/components/editor` — Tiptap 기반 위지윅. 서식·정렬·표·링크·본문 이미지(드래그로 크기 조절)·HTML 직접 편집.
  저장 정본은 **ProseMirror JSON** 이고, HTML 은 백엔드가 같은 스키마(`editor/schema.ts`)로 파생시킨다.
- `src/components/photo-uploader` — 사진 여러 장 업로드 + 끌어서 순서 변경(@dnd-kit). 첫 장이 대표 사진.

게시판의 `writeMode` 로 어느 화면을 쓸지 정한다 (`editor` 기본 / `photo`). 어느 쪽으로 써도
저장 형식이 같아서 나중에 바꿔도 기존 글은 그대로 보인다.

> **업로드는 아직 데모다.** `src/lib/upload.ts` 가 브라우저 임시 URL(`URL.createObjectURL`)을 돌려주므로
> 새로고침하면 사라진다. 백엔드가 붙으면 이 함수만 실제 업로드로 바꾸면 된다.

## IT 소식 · 스펙 비교

다른 게시판과 달리 **회원 글이 아니라 어드민이 관리하는 콘텐츠**다. 그래서 글쓰기 버튼·말머리 칩·
페이지 번호·게시판 검색이 없고, 화면도 매거진 / 기종 카드로 따로 그린다.

- 데이터: `src/data/content.ts` (초기값) → `src/lib/content-store.ts` (조회·수정)
- 화면: `src/components/news/*`, `src/components/specs/*`
- 비교표와 상세의 항목은 `components/specs/spec-rows.ts` 한 곳에서 정의한다 — 항목을 추가할 때 **비교 규칙**도 같이 정한다

### 비교 규칙

| 규칙 | 뜻 | 항목 |
| --- | --- | --- |
| `higher` | 클수록 낫다 | 주사율, 메모리, 배터리, 충전, 후면 카메라 |
| `lower` | 작을수록 낫다 | 출고가, 무게 |
| `tier` | 칩셋 등급으로 비교 | 칩셋 |
| `neutral` | 우열 없이 차이만 | 화면 크기 |
| `none` | 비교 안 함 | 출시, 저장공간, 전면 카메라 |

- 표시용 문자열(`battery: '4000mAh'`)과 비교용 숫자(`batteryMah: 4000`)를 나눠 저장한다.
  문장에서 숫자를 긁어내면 표기가 조금만 달라져도 깨지기 때문이다. 숫자가 0이면 그 항목은 비교에서 빠진다.
- **칩셋은 따로 관리한다**(`Chipset`). 같은 칩을 여러 기종이 쓰고, 벤치 점수는 종류에 따라 순위가 뒤집히며
  같은 칩이라도 기기 발열 설계에 따라 성능이 달라서 **4단계 등급**(플래그십·준플래그십·중급·보급형)으로만 비교한다.
  등급이 같으면 '동급'으로 표시하고 서열을 매기지 않는다.
- 우세 표시는 색만 쓰지 않는다 — 옅은 배경 + 굵은 글씨 + 체크 아이콘을 함께 쓴다.

> **아직 이 브라우저에만 저장된다** (localStorage). 어드민에서 고치면 사이트에 바로 반영되지만
> 다른 사람에게는 보이지 않는다. 백엔드가 붙으면 `content-store.ts` 만 API 호출로 바꾸면 된다.

## 디자인

- 브랜드 색 `#fa6038` 를 `zz-50 ~ zz-950` 스케일로 쓴다 (`frontend/src/app/globals.css` 의 `@theme`).
- 로고는 살짝 기울어진 체크마크 + 워드마크 (`components/layout/Logo.tsx`).
- 판매자·인증 표시는 초록(`shop-*`), 통신사는 각 사 색을 따른다.
- 본문 기본 15px, 제목은 굵고 큼직하게. 카드 모서리는 `rounded-2xl`.
